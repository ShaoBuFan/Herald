# Herald

从零构建的 AI 编程 agent harness（智能体框架）。本项目用于学习，不以产出可用产品为目标。

---

## 背景与动机

ZCode、Claude Code、Codex 等编程 agent 已能满足日常开发需求。但仅作为使用者，有两个问题难以通过阅读文档解决。

**其一，故障时缺少判断依据。** 当 agent 行为偏离预期时，无法区分原因来自模型能力、指令表述，还是上下文管理策略。缺少这种区分能力，只能依赖反复尝试。

**其二，设计决策的依据不可见。** 现有 harness 在实现上存在多处表面相似、取舍不同的选择，例如会话记录采用追加式日志还是消息数组。公开文档通常只说明最终方案，较少说明被否决的方案及其原因。

本项目通过完整实现一遍，使这些设计决策的依据可被验证，而不只是接受结论。

## 目标

判断项目是否成功的标准不是代码可运行——那只是必要条件——而是：

> 能够独立说明各层的设计理由、被否决的替代方案，以及所选方案的代价。

## 方法

每个模块按同一顺序推进：

1. 自行设计并实现初版
2. 对照已有实现（DeepSeek Harness、ZCode、Codex、Claude Code），重点关注其未采用的方案
3. 依据比较结果修改

被否决的方案通常比最终方案更有参考价值，因为它说明了该方案被排除的原因。

关键决策记录在 `docs/decisions/`，包含四项内容：问题、所选方案、被否决的方案、代价。

## AI 协作方式

本项目有 AI 助手参与，分工如下：

- **核心逻辑由项目作者编写。** 涉及设计决策的部分均不由 AI 代劳。
- **AI 助手负责**：环境配置、测试替身编写、依赖问题排查、代码审查，以及在作者停滞时提供思路而非实现。
- **设计讨论由双方共同进行。**

这使开发速度低于完全由 AI 生成的同类项目，属于预期内的取舍。
