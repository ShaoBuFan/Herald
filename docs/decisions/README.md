## 一、现在就该定的（阻塞阶段一）

### 0001. 消息数组要不要保留「思考」与「行动」的结构区分

- **分歧**：把模型的思考与工具调用都塞进同一套消息，还是让数组显式区分两者？
- **候选方向**：
  - A. 统一结构，靠 `role` / 内容块类型隐式区分（更贴近 OpenAI 原生格式）
  - B. 显式区分 Thought 与 Action（ReAct 的结构；思考不产生 observation，行动产生）
  - C. 先统一，留一个字段位，等接 thinking 通道时再启用
- **证据**：[`react-prehistory.md`](../research/react-prehistory.md) §7 第 2 条（ReAct 的结构性发现：Thought 不产生 observation、Action 产生）；[`react-lineage.md`](../research/react-lineage.md) §8（文本 ReAct → 原生工具调用时「可见推理轨迹」如何丢失，以及它如何以 thinking 通道回来）
- **为什么现在定**：它直接决定阶段二事件日志要记什么。阶段一刻意不用事件日志，但这一步做错，阶段二要重做消息数组。

### 0002. 循环的退出条件用什么

- **分歧**：退出由谁决定？模型说「完成」算不算？
- **候选方向**：
  - A. 步数上限（ReAct 用 7 / 5）
  - B. 成本上限（token 或金额）
  - C. 显式停止工具，由模型调用
  - D. 外部真值信号（测试通过、diff 为空）
  - 组合以上多个
- **证据**：[`react-prehistory.md`](../research/react-prehistory.md) §7 第 3 条；[`react-lineage.md`](../research/react-lineage.md) §7（2023 年无界循环的第 1 条失败机制正是「没有非模型意见的终止信号」）
- **注意**：A/B 与 C 可以并存，真正要定的是**哪个是主判据**。

### 0003. 工具校验在什么位置做，失败怎么处理

- **分歧**：两个可以分开也可以合并的问题——(a) 校验发生在执行前还是执行后；(b) 校验失败是回灌成 observation 还是抛异常中断。
- **候选方向**：
  - 校验位置：前置拦截 / 后置回灌 / 两者都要（前置拦不可逆操作，后置回灌可恢复错误）
  - 失败处理：当作 observation 回灌，模型自己恢复 / 抛错结束本轮
- **证据**：[`react-prehistory.md`](../research/react-prehistory.md) §5.3（三条路径与各自代价；SayCan 的 84% → 67% 消融量化了世界接地的作用）；§7 第 5 条
- **注意**：把两问合并成一个决策会让「代价」一节写不清——它们否决的方案不是同一批。

### 0004. 阶段一的第一个工具选什么

- **分歧**：只做 `read_file`，还是额外做一个**会失败**的工具？
- **候选方向**：
  - A. 只做 `read_file`（最小闭环，交付物明确）
  - B. `read_file` + 一个会失败的工具（如受限的 `grep`，文件不存在、无匹配、模式非法都是真实失败）
- **证据**：[`react-prehistory.md`](../research/react-prehistory.md) §7 第 4 条（ReAct 失败案例中 23% 来自检索无效，而它把失败当 observation 回灌；但那只读工具的闭环练不到这段语义）
- **注意**：这是**流程决策**（学什么先），不是架构决策。ADR 记录它有点勉强，但模板要求的问题项「若不存在分歧则不值得记录」在这里成立——B 的代价是阶段一交付物变模糊。

## 二、有分歧但不阻塞阶段一

### 0005. `LlmAdapter` 要不要为「多次采样」预留接口

- **分歧**：Self-Consistency 要同一问题采样几十条路径。这个能力要不要进接口？
- **候选方向**：A. 不预留，只覆盖「一条轨迹、多轮工具调用」；B. 接口层支持 `n` 参数，即使实现先只用 1
- **证据**：[`react-prehistory.md`](../research/react-prehistory.md) §2.3（CoT-SC 的机制与其在 agent 语义下的不成立：每步有副作用，采样几十条带副作用的轨迹要么全部回滚要么只对只读侧投票）；§7 第 1 条
- **注意**：真要做时，「同一问题跑 N 次」是不是同一个接口的问题——也可能该单独立项。

## 三、阶段三才需要，现在只登记

### 系统提示的措辞需要可评测

- **问题**：怎么避免「改一句看起来意思差不多的话」变成赌注？
- **证据**：[`react-prehistory.md`](../research/react-prehistory.md) §2.6（16 种触发句，最好 78.7、最差 9.3，基线 17.7；同为「鼓励思考」的措辞内部差 33 个点）；§7 第 6 条
- **为什么现在不写 ADR**：它需要先有系统提示装配和评测夹具，现在没有可对比的对象。

### 上下文成本要不要算调用次数

- **问题**：成本估算只看 token 数，还是也算提示模板的调用次数？
- **证据**：[`react-prehistory.md`](../research/react-prehistory.md) §2.6（Zero-shot CoT 是两次调用，论文自己把它与 few-shot 的示例工程做了明确交换）；§7 第 7 条
